# dsh-desktop — DeepSeek Harness Desktop Client

English | [中文](README.zh.md)

A Tauri 2 desktop shell that embeds the dsh web UI in a native window, with a bundled Node runtime and a pruned dsh distribution: works out of the box, stays running when the window closes (tray resident), and restarts automatically if the service crashes. **It does not modify any upstream `packages/` / `apps/cli` code.** The four agent presets (`standard` / `code` / `minimal` / `cordis`) come from upstream unchanged.

## Architecture

```
src-tauri/            Rust shell
  src/dsh_runner.rs   dsh child-process lifecycle: spawn `dsh web --port 3081 --no-open`, port health probe, crash auto-restart (does not race when dsh-plugin restarts itself)
  src/tray.rs         tray residency: closing the window hides it; only tray Quit ends the process tree
  src/setup.rs        first-run wizard commands: write preset into the profile patch (agent-presets.config.default), install plugins (dsh plugin / local copy)
ui/dist/              shell frontend (pure static, no build): index.html full-window iframe + error banner; wizard.html first-run wizard
scripts/bundle-runtime.mjs  pack Node runtime + pnpm-deployed dsh closure + local plugins → runtime/
scripts/generate-mac-icons.mjs  rewrite src-tauri/icons/icon.icns from the tile master onto Apple's 824/1024 icon grid (see the script header)
runtime/              packaging output (not committed; generated by CI; tauri.conf.json maps it as bundle resources)
```

Icons: the committed tile (`src-tauri/icons/official-512.png`) composes edge to edge, which is right for the Windows `icon.ico` but makes the macOS Dock render the bundle ~25% larger than system icons. `icon.icns` is committed regenerated (`node scripts/generate-mac-icons.mjs`): every size is the master scaled by 824/1024 onto a transparent, centered canvas — proportions, corner radius, and anti-aliasing stay exactly the design's; the `.ico` and the PNG family keep the Windows look.

Port contract: the shell spawns `dsh web --port 3081 --no-open`, scans upward from 3082 when that loopback port is occupied, and captures the one-time authenticated URL printed by dsh. The shell then splits by webview engine. Windows (WebView2/Chromium): `authenticate_webview` exchanges the token over loopback HTTP (also a liveness probe) and installs the signed browser cookie into the native WebView cookie store (`SameSite=None; Secure` — an embedded cross-origin iframe cannot carry the server's `SameSite=Strict` cookie on Chromium), and the iframe loads the clean URL it returns. WebKit shells (macOS/Linux): `navigate_main` opens the dsh UI in its own window created against the token URL (the supervisor repeats it on every later readiness with a same-origin guard); the same exchange pre-installs the signed session into the shared WebView cookie store as `SameSite=Lax` without `Secure` first, because WKWebView drops the 303's `HttpOnly; SameSite=Strict` cookie for the redirect follow even in a fresh window while the same URL works in Safari — the app document is then authenticated by two independent channels (the server's own mint when the webview honours it, the pre-installed copy otherwise), and leftover top-level navigations route to the system browser by the window navigation policy. The shell page stays loaded in the hidden main window as the wizard/splash/error surface, and a dead server closes the app window and brings it back. `dsh://ready` carries `{ url }` and `dsh_status` reports `{ running, port, url }`. CLI `dsh web` still defaults to 3080. `/api` (including `host.openPath`, WebSocket downlink, SSE) is entirely served by dsh itself; the shell does not reverse-proxy. The shell does not render a top navigation bar — the interface is entirely the dsh UI; on Windows, shell and iframe only exchange host-bridge messages (`source: 'dsh-desktop-host'` for notifications and external links).

## Development

Prerequisites: Node ≥ 22.19, pnpm ≥ 11, Rust ≥ 1.77, Tauri CLI (provided as a devDependency of this package).

```sh
pnpm install                # workspace dependencies
pnpm run build              # produce lib and apps/web/dist (static frontend for dsh web)
pnpm tauri dev              # from apps/desktop-tauri; dev mode uses PATH node + apps/cli/lib/bin.js
```

Dev mode needs built CLI artifacts (`pnpm run build`); you can also override runtime resolution with environment variables:
`DSH_DESKTOP_NODE` (node executable), `DSH_DESKTOP_DSH_BIN` (dsh CLI entry), `DSH_DESKTOP_PLUGINS_DIR` (local plugins directory).

## Building a release

```sh
pnpm run build              # repository artifacts
node scripts/bundle-runtime.mjs --platform win   # win|mac|linux; generates runtime/
pnpm tauri build            # package installers (runtime/ is bundled as resources)
```

CI (`.github/workflows/desktop-release.yml`) runs the same flow on a three-platform matrix and uploads to GitHub Release; trigger with a `v*` tag or manual dispatch.

## First launch

- Default preset: `standard` (changeable to `code` / `minimal` / `cordis`; written as `agent-presets.config.default` in `~/.dsh/profiles/web/cordis.patch.yml`)
- Default plugins: `dsh-plugin` (plugin center/market), `dsh-win-terminal-inspector` (Windows only; local copy + patch insert)
- Optional plugins: `dsh-better-sidebar`, `dsh-notification`, `dsh-session-context-menu`, `@xmanrui/dsh-im` (WeCom/Feishu/DingTalk/WeChat/QQ and 9 channels), `dsh-lark`, `dsh-qqbot`, `dsh-vision-router`, `graph-memory`, `aegis`
- Data location: `<Documents>/Easel-dsh` by default (the OS Documents folder, including OneDrive redirection); Settings → Data location can move it. Old paths remain as junctions/symlinks, so existing projects keep working without rewriting project files.

Plugin install/update/uninstall all go through official dsh mechanisms (`dsh plugin` / the dsh-plugin center); the runtime ships pnpm from the same version family.
