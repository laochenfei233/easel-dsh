# 安装包能力一致性（macOS 更新 / 备份 / 隔空传送）

## Report

**What was built** — macOS/Linux 桌面壳的关于页现在通过 Tauri IPC 调用更新命令：`build.rs` 用 app manifest 生成 14 个 `allow-*`，`capabilities/app-window.json` 把四个更新命令限定给 `app` 窗口的 `http://127.0.0.1:*`，`capabilities/default.json` 覆盖 shell 页面调用的全部应用命令；Windows 的 iframe relay 不变。`apps/cli` 恢复 `@deepseek-ai/dsh-easel-backup` 与 `@easel-dsh/easel-air-transfer`，安装包重新带上备份引擎与隔空传送；`bundle-runtime.mjs` 在 deploy 后校验闭包并在打包期编译注入脚本。发布侧：`uploadUpdaterJson` 对所有平台开启（原 `includeUpdaterJson` 是 tauri-action 0.x 的输入名，v1 已忽略），镜像同步器把 `.app.tar.gz` + `.sig` 解析成 `darwin-*` 写进 `latest.json`，`downloads.json` 保持 Windows-only。

**Verification** — `node --test site/server/sync-releases.test.mjs` 10/10；`vitest run scripts/desktop-host-bridge.spec.ts` 4/4；新 spec 的 `tsc --noEmit --strict` 通过；`node --check bundle-runtime.mjs`、capability JSON 解析、oxlint 通过；`corepack pnpm install --frozen-lockfile` 通过；`verify-translation-pairing apps/desktop-tauri/README.md` 通过。未运行：cargo/tauri build（本机无 Rust 工具链）与完整 runtime 打包。`test:docs` 的 6 个失败为基线（全部 compose spec 的中英配对提示、`.changelog` 的提交哈希、无关包 README），本改动文件不再新增条目；`check-workspace-constraints` 的 lan-handoff `private` 失败在基线同样存在。

**Journey log** — ①首版只改注入桥；审阅指出 Tauri 2.11+ 对远程来源同样强制 ACL，补 app manifest 与两份 capability。②`includeUpdaterJson` 是 tauri-action 0.x 的输入名，v1 已改为 `uploadUpdaterJson`，原排除 mac 的条件从未生效。③官方镜像自己重建 `latest.json` 且只收 Windows 资产，拆分 `updaters` 与下载页集合。④mac 安装完成后进程退出、不自动重开（与关于页「应用即将退出」一致），自动重开列为后续体验项。

## [S1] Problem

macOS 桌面版（Tauri + WebKit）里三处已交付能力不可用：

1. 「设置 → 关于」显示「应用版本与更新检查仅在桌面版提供。」，无法检查/安装更新。
2. 「设置 → 备份」显示「本安装缺少备份引擎，重新安装 Easel 后可用。」，且重装无效。
3. 「设置 → 隔空传送」显示当前 profile 未启用隔空传送。

前两项已在本机安装 `/Applications/Easel-dsh.app` 复现并定位：

- **更新**：`apps/desktop-tauri/scripts/bundle-runtime.mjs` 的 `injectNotificationBridge` 只在 `window !== window.parent` 时安装 `__easelHostUpdate`（Windows WebView2 的 iframe 形态）。macOS 走 `open_app_window`，dsh 页面是顶层文档，脚本在首行 `return`，桥不存在，`createUpdateStore` 退化为 `supported: false`。
- **备份 / 隔空传送**：两者的运行时包是 `apps/cli` 部署闭包的成员（`docs/compose/specs/easel-settings-backup.md` §S2、`easel-handoff-payload.md` 同名约定）。「merge(easel): the upstream dsh 0.2.2-alpha.2 sync」合并时把 `@deepseek-ai/dsh-easel-backup` 与 `@easel-dsh/easel-air-transfer` 从 `apps/cli/package.json` 丢掉，`pnpm deploy` 产出的 `runtime/dsh/node_modules` 因此没有这两个包：`lib/backup.js` 的动态 import 失败（`engineMissing`），`@easel-dsh/easel-air-transfer` 行解析失败（隔空传送服务缺席）。

两处都是安装形态缺陷，与用户数据无关；重新安装同一版本无法恢复。

## [S2] Design

### S2.1 macOS 顶层窗口的宿主桥

WebKit 的 app 窗口没有 iframe 父页面可 postMessage，也不再走 shell 页面的 relay。桥改为按传输能力二选一：

- **frame 形态（Windows 不变）**：`window.parent.postMessage` + `rpc-result` / `rpc-event`，沿用 `ui/dist/app.js` 的 relay。
- **顶层形态（macOS/Linux WebKit）**：页面直接调用 `window.__TAURI__.core.invoke` 与 `window.__TAURI__.event.listen`；动作到命令的映射与 `ui/dist/app.js` 的 `UPDATE_RPC` 相同（`update-state|check|install|source-set` → `easel_update_state|check|install|set_update_source`）。
- 两种传输都没有时（普通浏览器 `dsh web`）保持早退，页面不注入任何全局对象。
- 顶层形态的事件订阅把 `listen()` 的 Promise 包成同步退订函数，满足 `createUpdateStore` 的 `onEvent` 契约。

启用 IPC 需要两条：`build.rs` 用 `AppManifest::commands` 登记 `generate_handler!` 里的全部应用命令（Tauri 2.11 起远程来源调用应用命令同样过 ACL，`is_local=false` 且无 app manifest 时一律拒绝）；capability `app-window` 只给 `app` 窗口 `http://127.0.0.1:*` 的四个 `allow-easel-*` 与 `core:event:default`。定义 app manifest 后本地窗口也走 ACL，因此 `capabilities/default.json` 补上 shell 页面与 relay 用到的全部应用命令 `allow-*`。`tauri.conf.json` 未显式列出 `app.security.capabilities`，新文件自动生效；`permissions/autogenerated/` 是构建产物，加入 `.gitignore`。

### S2.2 部署闭包恢复与打包期门禁

- `apps/cli/package.json` 恢复两条依赖：`@deepseek-ai/dsh-easel-backup`、`@easel-dsh/easel-air-transfer`（`workspace:*`），同步 `pnpm-lock.yaml`。
- `bundle-runtime.mjs` 在 `pnpm deploy` 之后校验闭包里确有这两个包；缺失时抛错终止打包，把「静默少包」变成打包期失败，而不是用户安装后才发现的提示。

### S2.3 macOS 应用内更新

桥接只负责让关于页能调命令；mac 能真正更新还需要发布清单包含 mac 条目。`desktop-release.yml` 的 `includeUpdaterJson` 改为所有平台（mac 包仍不带 Apple 代码签名，更新包由 minisign 校验），更新清单因此带上 `darwin-x86_64` / `darwin-aarch64`。安装由 `tauri-plugin-updater` 就地替换 `.app` 包，替换后进程退出、用户重开应用；这与关于页「应用即将退出」的文案一致。

官方镜像（`site/server/sync-releases.mjs`）自己重建 `latest.json`，原先只收 Windows 的 `*-setup.exe`，会把 mac 客户端挡在没有 darwin 条目的清单上。同步器新增 `updaters` 集合：Windows 安装包原样进入，mac `.app.tar.gz` + `.sig` 解析为 `darwin-*` 条目并镜像到同域；`downloads.json` 保持 Windows-only，避免下载页渲染未知平台。

## [S3] Scope

- In scope：
  - `apps/desktop-tauri/scripts/bundle-runtime.mjs`（桥的顶层分支 + 闭包校验 + 注入脚本编译校验）
  - `apps/desktop-tauri/src-tauri/build.rs`（app manifest 命令表）
  - `apps/desktop-tauri/src-tauri/capabilities/app-window.json`、`capabilities/default.json`
  - `apps/cli/package.json`、`pnpm-lock.yaml`
  - `.github/workflows/desktop-release.yml`（mac 更新产物进入 latest.json）、`site/server/sync-releases.mjs` + 测试（镜像清单纳入 darwin）、桌面壳中英文 README 的更新器章节
  - `scripts/desktop-host-bridge.spec.ts`（桥三形态的 VM 测试）
- Out of scope：
  - macOS 原生通知与外部链接行为（同一段脚本，但本次不改变其 transport 语义）
  - Apple 代码签名与公证（应用包仍未签名）
  - 发布后的真机更新验收（需要下一次 Release 产物）
  - AirDrop 系统分享（与本问题无关）
